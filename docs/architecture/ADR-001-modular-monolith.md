# ADR-001：模块化单体与独立前后台

状态：已接受

## 决策

V2 使用 pnpm Monorepo。消费者商城与运营后台保持独立部署单元，交易 API 使用 NestJS 模块化单体。核心交易首先在同一数据库事务边界内完成，异步副作用通过事务 Outbox 与 BullMQ 投递。

## 原因

首期交易一致性、交付速度和可观测性优先于微服务拆分。库存锁定、优惠核销、订单快照和支付记录可以在单一 PostgreSQL 事务中原子提交，避免过早引入分布式事务。

## 演进边界

目录、支付、履约、营销、分销、财务、AI 均通过模块接口隔离。当独立扩容需求得到生产数据验证后，可按 Outbox 事件拆分服务。
