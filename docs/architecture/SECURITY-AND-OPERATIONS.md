# 安全、稳定性与运维基线

## 交易稳定性

- PostgreSQL 是订单、库存、优惠、支付与佣金的事实来源；Redis 不保存不可恢复的交易事实。
- 下单事务使用条件库存更新、版本号、唯一约束、持久幂等记录和 Outbox。
- 支付适配器统一执行签名、商户号、订单号、金额、币种和渠道流水号校验。
- 定时任务关闭超时订单并释放库存；支付晚到时进入可恢复异常队列，不直接覆盖订单状态。
- 对账按渠道和营业日唯一，差异只能通过补偿流水处理。

## 安全

- 密码使用 Argon2id；访问令牌 15 分钟；刷新令牌哈希后写入会话表并通过 HttpOnly Cookie 传递。
- 商家及管理员接口强制 RBAC 与 `merchant_id` 数据隔离；批量发布、退款、提现和密钥操作要求二次确认。
- eSIM 激活码仅保存 KMS 信封密文；展示前要求登录、二次验证、频率限制与审计。
- 地址、电话、税号、物流单号和 AI 日志中的个人信息必须加密或脱敏。
- 图片和导入文件执行扩展名、MIME、文件签名、大小、行数、恶意内容扫描与隔离桶检查。

## 生产门禁

本机未安装 Docker，因此当前未执行 PostgreSQL/Redis 容器集成测试和故障注入。正式上线前必须在 CI 或预生产环境完成数据库恢复、Redis 重启、支付回调乱序、最后库存并发、灰度回滚和密钥轮换演练。
